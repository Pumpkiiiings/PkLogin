---
title: Migrar entre motores
description: Copia todas las cuentas a otro motor de base de datos sin empezar de cero.
---

`/pklogin migrate <motor>` copia todas las cuentas del motor que estás usando a otro, así que
cambiarte no significa empezar de cero.

## Pasos

<Steps>

<Step>

### Completa los datos de conexión del motor nuevo

Edita el bloque `Database` con los datos del motor al que te vas, pero deja `type` apuntando
al que estás usando ahora:

```yaml title="config.yml"
Database:
  type: sqlite          # sigue siendo el motor actual

  host: localhost
  port: 5432            # PostgreSQL, no el 3306 que viene puesto
  database: pklogin
  username: pklogin
  password: "..."
```

</Step>

<Step>

### Ejecuta la migración

```
/pklogin migrate postgresql
```

Destinos válidos: `sqlite`, `h2`, `mysql`, `mariadb`, `postgresql`.

La copia corre en segundo plano y avisa del progreso cada 100 cuentas.

</Step>

<Step>

### Cambia el motor y reinicia

Ponle a `Database.type` el motor nuevo y reinicia el servidor. `/pklogin reload` no reabre la
conexión.

```yaml title="config.yml"
Database:
  type: postgresql
```

</Step>

</Steps>

## Lo que el comando no toca

- **No borra nada.** La base de datos vieja queda tal cual estaba, y ese es tu plan B: dejas
  `type` como estaba y reinicias.
- **No te edita el `config.yml`.** El cambio lo haces tú, después de comprobar que la copia
  quedó bien.

## Lo puedes correr las veces que quieras

Las cuentas que ya estén en el destino se saltean, así que una segunda pasada solo copia lo
que falte.

<Callout type="warn" title="Fíjate el puerto antes de migrar">
  El `port: 3306` que viene puesto sirve para MySQL y MariaDB. PostgreSQL escucha en el
  **5432**. Si apuntas al puerto equivocado, la migración falla al conectar y no a mitad de
  camino, pero igual te hace perder un reinicio de gusto.
</Callout>
