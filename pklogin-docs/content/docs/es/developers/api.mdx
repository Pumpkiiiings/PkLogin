## Agregar la dependencia

Las clases de la API están en `com.pumpkiiings.pklogin.api` y van shadeadas adentro del jar
del plugin, así que depende de `pklogin-universal` y márcalo como `provided`.

<Tabs items={['Gradle', 'Maven']}>

<Tab value="Gradle">

```groovy title="build.gradle"
repositories {
    maven { url = uri('https://repo.pumpkiiings.com/maven-releases/') }
}

dependencies {
    compileOnly('com.pumpkiiings.pklogin:pklogin-universal:2.0')
}
```

</Tab>

<Tab value="Maven">

```xml title="pom.xml"
<repositories>
  <repository>
    <id>pumpkiiings-repo</id>
    <url>https://repo.pumpkiiings.com/maven-releases/</url>
  </repository>
</repositories>

<dependencies>
  <dependency>
    <groupId>com.pumpkiiings.pklogin</groupId>
    <artifactId>pklogin-universal</artifactId>
    <version>2.0</version>
    <scope>provided</scope>
  </dependency>
</dependencies>
```

</Tab>

</Tabs>

<Callout title="Fíjate la versión">
  `2.0` es la versión que hay en el `build.gradle` de este repositorio. Usa la que esté
  publicada en la [página de releases](https://github.com/Pumpkiiiings/PkLogin/releases) en
  ese momento.
</Callout>

## Por dónde se entra

Todo pasa por `PkLoginProvider`:

```java
import com.pumpkiiings.pklogin.api.service.AccountManagerAPI;
import com.pumpkiiings.pklogin.api.service.PkLoginProvider;
import com.pumpkiiings.pklogin.api.service.SecurityAPI;
import com.pumpkiiings.pklogin.api.service.SessionAPI;

AccountManagerAPI accounts = PkLoginProvider.getAccountManager();
SecurityAPI security = PkLoginProvider.getSecurityAPI();
SessionAPI sessions = PkLoginProvider.getSessionAPI();
```

Cada getter tira `PluginNotLoadedException` si PkLogin todavía no registró ese servicio.
Declara PkLogin como dependencia de tu plugin para que cargue antes, y pide los servicios
cuando los vayas a usar en vez de guardarlos en un campo estático.

<Callout type="warn" title="PkLoginAPI quedó deprecada">
  La interfaz vieja `PkLoginAPI`, que tenía todo junto, sigue existiendo pero está marcada
  como `@Deprecated`. Sus métodos son síncronos y bloquean esperando a la base de datos. Usa
  los tres servicios de abajo.
</Callout>

## AccountManagerAPI

```java
public interface AccountManagerAPI {
    CompletableFuture<Optional<AccountData>> getAccount(String name);
    CompletableFuture<Optional<AccountData>> getAccount(UUID uuid);
    CompletableFuture<Boolean> isRegistered(String name);
    CompletableFuture<Void> deleteAccount(String name);
}
```

`getAccount` devuelve un `Optional` vacío cuando el jugador no está registrado.

### AccountData

```java
public interface AccountData {
    String getRealName();
    String getAddress();
    String getUuidType();
    String getRandomUuid();
    String getDiscordId();
    String getEmailAddress();
    long getLastLogin();
    long getRegDate();
}
```

`getUuidType()` devuelve el modo de la cuenta como texto: `REAL`, `RANDOM` u `OFFLINE`. Mira
[Tipos de UUID](/es/docs/getting-started/premium-login#tipos-de-uuid).

## SecurityAPI

```java
public interface SecurityAPI {
    CompletableFuture<Boolean> changePassword(String name, String newPassword);
    CompletableFuture<Boolean> comparePassword(String name, String rawPassword);
}
```

`comparePassword` hashea lo que le pases con los parámetros guardados y lo compara de forma
segura. `changePassword` se encarga del hashing con lo que digas en `Security.hash-algorithm`,
y tira abajo la sesión de login que la cuenta tenga abierta.

## SessionAPI

```java
public interface SessionAPI {
    boolean isAuthenticated(String name);
    boolean isAuthenticated(UUID uuid);
    CompletableFuture<Boolean> forceLogin(String name);
}
```

Los dos `isAuthenticated` son **síncronos**: leen estado que está en memoria y los puedes
llamar desde el hilo principal sin problema. `forceLogin` no.

## Hilos

Todo método que toca la base de datos devuelve un `CompletableFuture`. La API no te devuelve
sola al hilo del servidor en los callbacks, así que vuelve tú antes de tocar cualquier cosa
del mundo:

```java
PkLoginProvider.getAccountManager()
    .isRegistered(player.getName())
    .thenAccept(registered -> {
        if (!registered) return;

        Bukkit.getScheduler().runTask(plugin, () -> {
            player.sendMessage("Bienvenido de vuelta.");
        });
    });
```

<Callout type="warn" title="No bloquees esperando los futures">
  Llamar a `.join()` o `.get()` desde el hilo principal te congela el servidor todo lo que
  tarde la consulta a la base de datos, que es justamente lo que la API asíncrona existe para
  evitar.
</Callout>

## Excepciones

| Excepción | Cuándo se tira |
| --- | --- |
| `PluginNotLoadedException` | Pediste un servicio antes de que PkLogin lo registrara. |
| `AccountNotFoundException` | La operación apunta a un nick que no tiene cuenta. |
| `InvalidPasswordException` | Una contraseña no pasa la validación. |
| `DatabaseException` | Falló la llamada a la base de datos. |

Todas están en `com.pumpkiiings.pklogin.api.exception`.
