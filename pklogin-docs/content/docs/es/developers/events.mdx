---
title: Eventos
description: Los eventos de Bukkit y Velocity que lanza PkLogin, y cuáles se pueden cancelar.
---

## Bukkit / Paper

Todos están en `com.pumpkiiings.pklogin.api.event.bukkit`.

| Evento | ¿Se cancela? | Cuándo se lanza |
| --- | --- | --- |
| `AsyncLoginEvent` | Sí | Un jugador está por entrar con `/login`. |
| `AsyncRegisterEvent` | Sí | Un jugador está por registrarse con `/register`. |
| `AsyncAuthenticateEvent` | No | Un jugador quedó autenticado, por donde sea. |
| `auth.PlayerAuthLoginEvent` | No | Un jugador se logueó o se registró bien. |
| `auth.PlayerPasswordChangeEvent` | No | Un jugador se cambió la contraseña desde el juego. |

`AsyncLoginEvent`, `AsyncRegisterEvent` y `AsyncAuthenticateEvent` extienden `PkLoginEvent` y
se lanzan de forma **asíncrona**.

### El que normalmente quieres es AsyncAuthenticateEvent

Se lanza pase lo que pase para llegar a autenticado: `/login`, `/register`, un 2FA
completado, un login automático premium, un login automático de Bedrock, una sesión que se
retomó, y también cuando el proxy le avisa al backend que el jugador ya está autenticado.
Los otros eventos cubren un solo camino cada uno.

```java
@EventHandler
public void onAuthenticate(AsyncAuthenticateEvent event) {
    Player player = event.getPlayer();

    Bukkit.getScheduler().runTask(plugin, () -> {
        player.sendMessage("Autenticado.");
    });
}
```

<Callout type="warn" title="Estos eventos son asíncronos">
  La API de Bukkit no es thread-safe. Vuelve al hilo principal antes de tocar el mundo, el
  inventario del jugador o cualquier otra cosa del servidor.
</Callout>

### Cancelar un login

```java
@EventHandler
public void onLogin(AsyncLoginEvent event) {
    if (isBanned(event.getPlayer())) {
        event.setCancelled(true);
    }
}
```

Cancelar `AsyncLoginEvent` o `AsyncRegisterEvent` corta ese intento puntual.
`AsyncAuthenticateEvent` no se puede cancelar: cuando se lanza, la decisión ya está tomada.

## Velocity

Todos están en `com.pumpkiiings.pklogin.api.event.velocity.auth`, y los lanza el
`EventManager` de Velocity. Ninguno se puede cancelar.

| Evento | Cuándo se lanza |
| --- | --- |
| `VelocityPreLoginEvent` | Durante el `PreLoginEvent` del proxy, antes de que PkLogin decida modo online u offline. Te da `getUsername()`. |
| `VelocityPlayerAuthLoginEvent` | Un backend le avisó al proxy que el jugador se autenticó. Te da `getPlayer()`. |
| `VelocityPlayerPasswordChangeEvent` | Un jugador se cambió la contraseña. Te da `getPlayer()`. |

```java
@Subscribe
public void onAuthLogin(VelocityPlayerAuthLoginEvent event) {
    Player player = event.getPlayer();
    // ...
}
```

<Callout title="VelocityPreLoginEvent es solo informativo">
  Se lanza antes de que PkLogin resuelva si el nick es premium, dentro de la tarea asíncrona
  del handshake del proxy. Escucharlo no te deja cambiar el resultado: para eso cambia el modo
  de la cuenta.
</Callout>

## Ojo: hay dos clases que se llaman PlayerPasswordChangeEvent

La que lanza PkLogin es
`com.pumpkiiings.pklogin.api.event.bukkit.auth.PlayerPasswordChangeEvent`. Hay otra clase con
el mismo nombre en `...event.bukkit.account` que no se usa: importa la del paquete `auth`.

Lo mismo pasa con `...event.bukkit.auth.PreLoginEvent`, que está declarado pero nunca se
lanza. En Bukkit, si necesitas esa etapa, engánchate al `AsyncPlayerPreLoginEvent` de Paper.
