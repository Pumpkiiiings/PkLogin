---
title: Referencia de config.yml
description: Todas las opciones del archivo principal, en el mismo orden en que aparecen.
---

`config.yml` está en `plugins/PkLogin/`. PkLogin mantiene un campo `version-config` arriba de
todo y va actualizando los archivos viejos al arrancar: agrega las opciones nuevas y te deja
tal cual lo que hayas cambiado. No toques ese campo a mano.

Casi todos los cambios se aplican con `/pklogin reload`. Los que no, están avisados más
abajo.

## Idioma

```yaml
languageFile: 'messages_en.yml'
```

Mira [Idiomas](/es/docs/configuration/languages) para la lista completa de archivos que
vienen incluidos.

## Security

```yaml
Security:
  # Segundos que tiene el jugador para loguearse o registrarse antes de que lo kickee.
  time-to-login: 45

  # BCRYPT (por defecto) | ARGON2 | PBKDF2 | SHA512 | SHA256
  hash-algorithm: BCRYPT

  hashing:
    bcrypt:
      cost: 12
    pbkdf2:
      iterations: 600000
    argon2:
      iterations: 2
      memory-kb: 65536
      parallelism: 1

  # Tiempo mínimo entre dos comandos de login del mismo jugador, en
  # milisegundos. Evita que un cliente mande intentos más rápido de lo que el
  # contador de fuerza bruta puede reaccionar.
  command-cooldown: 750

  session:
    enable: true
    timeout: 5

  # Los nicks que no coincidan quedan rechazados antes del login.
  valid-name-regex: '([a-zA-Z0-9_]{3,16})|(\*[a-zA-Z0-9_]{3,17})'

  password:
    small: 5
    large: 15

    secure:
      enable: false
      enforce: false
      secure-regex: '(?=\S*\d)(?=\S*[A-Z])(?=\S*[a-z])(?=\S*[!@#$%^&*?])\S*$'
```

Los detalles están en [Seguridad de contraseñas](/es/docs/configuration/security) y
[Sesiones](/es/docs/configuration/sessions).

## Database

```yaml
Database:
  # sqlite | h2 | mariadb | mysql | postgresql
  type: sqlite

  # Ruta absoluta, para compartir un archivo SQLite entre Velocity y el servidor
  # de auth. Vacío usa la ubicación de siempre.
  sqlite-file-path: ""

  host: localhost
  port: 3306
  database: pklogin
  username: root
  password: ""

  pool:
    maximum-pool-size: 10
    connection-timeout: 10000
    max-lifetime: 1800000
```

Cambiar `type` pide **reiniciar**, no alcanza con el reload. Mira
[Bases de datos](/es/docs/configuration/database).

## Login automático

```yaml
autologin:
  bedrock:
    enable: true
    skip-register: true

  premium:
    # Viene desactivado: con esto activado, un jugador offline que use el nick de
    # una cuenta premium no puede entrar.
    enable: false

    # Preguntarle al que acaba de registrar un nick premium si la cuenta es suya.
    question: true

    cache-minutes: 60
    session-timeout: 60
    mojang-timeout: 5000
```

Mira [Login premium sin contraseña](/es/docs/getting-started/premium-login).

## Two-factor

```yaml
two-factor:
  # Dígitos que tiene cada código. De 4 a 9.
  code-length: 6

  # Segundos que sigue valiendo un código de login.
  login-code-expiration: 300

  # Segundos que sigue valiendo un código de vinculación.
  link-code-expiration: 600

  # Códigos errados que se permiten antes de tirar abajo el código pendiente.
  max-verify-attempts: 5

  discord:
    max-link-attempts: 10
    link-attempt-window: 600
```

Los datos de cada proveedor están en `plugins/PkLogin/2fa/`. Mira
[Autenticación en dos pasos](/es/docs/configuration/two-factor).

## Username appender

Evita que se choquen los nicks de un jugador premium y uno cracked que se llaman igual.

```yaml
username-appender:
  enabled: false
  premium:
    username-appendix: ""
    position: "suffix"
    domains:
      - "premium.myserver.com"
  offline:
    username-appendix: "+"
    position: "suffix"
    domains:
      - "myserver.com"
```

El jugador cae en el grupo premium o en el offline según el host por el que se conectó, y al
nick se le agrega lo que corresponda. `valid-name-regex` se comprueba contra el nick que
escribió el jugador, antes de agregarle ningún sufijo.

## Teleport

```yaml
teleport:
  # Teletransportar a un lugar seguro al entrar.
  safe-location: true

  # Devolver al jugador a donde estaba después del login.
  last-location: true
```

El spawn de antes del login se pone desde el juego con `/pklogin setspawn`.

## Limbo

```yaml
limbo:
  hide-players-before-login: true
  block-player-walk: true
  blindness-effect: false

  inventory:
    hide-inventory: true

  # Velocidades que se le devuelven al jugador cuando se autentica. Son los
  # valores de vanilla: cámbialos solo si otro plugin de tu servidor usa otros.
  # Solo se aplican si block-player-walk está activado.
  restore:
    walk-speed: 0.2
    fly-speed: 0.1
```

## Seguridad general

```yaml
security:
  captcha:
    enable: false
    # INVENTORY | CHAT | MAP
    type: INVENTORY
    # Caracteres que tiene el código, para CHAT y MAP.
    code-length: 5
    # Bloquear todos los comandos hasta que resuelva el captcha.
    # /login y /register quedan bloqueados igual.
    blocked-commands: true

  ip-limit:
    enable: true
    limit: 3

  # Saltear la comprobación de "ese jugador ya está online" cuando la IP es la
  # misma con la que está registrado. Sirve cuando a un jugador se le cae la
  # conexión y vuelve a entrar.
  bypass-online-check-with-same-address: true
```

<Callout title="Ojo: hay dos bloques que se llaman security">
  `Security` (con S mayúscula) tiene los tiempos de login, el hashing, las sesiones y las
  reglas de contraseña. `security` (con minúscula) tiene el captcha, el límite por IP y la
  comprobación de online. Son dos bloques distintos en el mismo archivo.
</Callout>
