## Algoritmos

| Algoritmo | Notas |
| --- | --- |
| **BCRYPT** (por defecto) | Coste ajustable. La mejor opción para la mayoría. |
| **ARGON2** | Argon2id, el que ganó la Password Hashing Competition. El más seguro. |
| **PBKDF2** | El más estandarizado. 600.000 iteraciones, lo que recomienda OWASP en 2024. |
| **SHA512** | Con sal. Solo por compatibilidad, no lo uses en un servidor nuevo. |
| **SHA256** | Con sal. Solo por compatibilidad, no lo uses en un servidor nuevo. |
| AuthMe SHA256 | Solo lectura. Las cuentas importadas se migran solas en el primer login. |

```yaml title="config.yml"
Security:
  hash-algorithm: BCRYPT
```

<Callout title="Se cambia sin bajar el servidor">
  Cambia `Security.hash-algorithm` cuando quieras. Los hashes que ya existen se reconocen
  solos y se vuelven a hashear con el algoritmo nuevo en el siguiente login del jugador: no
  hay comando de migración ni queda nadie afuera.
</Callout>

## Ajustar el coste

Los valores más altos hacen más lentos tanto los logins normales como los intentos de fuerza
bruta, así que ajústalos a tu CPU. Busca que cada hash tarde unos **250 ms**.

```yaml title="config.yml"
Security:
  hashing:
    bcrypt:
      # Factor de trabajo. Cada +1 duplica el tiempo.
      cost: 12
    pbkdf2:
      iterations: 600000
    argon2:
      iterations: 2
      # Memoria por hash, en kibibytes. 65536 = 64 MB.
      memory-kb: 65536
      parallelism: 1
```

Si subes un valor, cada contraseña se vuelve a hashear en el siguiente login. Si lo bajas, no
debilita ningún hash que ya exista: cada uno se queda con los parámetros con los que se creó
hasta que el jugador vuelva a entrar.

<Callout type="warn" title="La memoria de Argon2 es por cada hash">
  `memory-kb: 65536` quiere decir que cada hash que se esté calculando al mismo tiempo reserva
  64 MB. Una avalancha de logins después de un reinicio los multiplica. Compáralo con la RAM
  que a tu servidor le sobra de verdad.
</Callout>

## Reglas de contraseña

```yaml title="config.yml"
Security:
  password:
    # Largo mínimo, incluido.
    small: 5
    # Largo máximo, incluido.
    large: 15

    secure:
      # Comprobar que la contraseña sea fuerte.
      enable: false

      # Obligar a los que ya están registrados a cambiar las contraseñas que no
      # cumplan el patrón.
      enforce: false

      secure-regex: '(?=\S*\d)(?=\S*[A-Z])(?=\S*[a-z])(?=\S*[!@#$%^&*?])\S*$'
```

El `secure-regex` que viene puesto pide un número, una mayúscula, una minúscula y uno de
estos: `!@#$%^&*?`.

## Protección contra fuerza bruta

```yaml title="config.yml"
passwords:
  bruteforce:
    max-login-tries: 3
```

Pasados esos intentos errados, al jugador lo kickea.

Junto a este hay un segundo límite:

```yaml title="config.yml"
Security:
  # Milisegundos mínimos entre dos comandos de login de un mismo jugador.
  command-cooldown: 750
```

Evita que un cliente mande intentos más rápido de lo que el contador puede reaccionar, que
importa porque el contador se revisa por cada intento y el hashing es lento a propósito.

## Límite de cuentas por IP

```yaml title="config.yml"
security:
  ip-limit:
    enable: true
    limit: 3
```

Limita cuántas cuentas se pueden registrar desde una misma IP.
`/pklogin dupeip <ip|jugador>` te lista las cuentas que comparten una IP.

## Nicks permitidos

```yaml title="config.yml"
Security:
  valid-name-regex: '([a-zA-Z0-9_]{3,16})|(\*[a-zA-Z0-9_]{3,17})'
```

Los nicks que no coincidan quedan rechazados antes de llegar al login. Si tienes
`username-appender` activado, la comprobación se hace sobre el nick que escribió el jugador,
antes de agregarle ningún sufijo.

## Captcha

```yaml title="config.yml"
security:
  captcha:
    enable: false
    # INVENTORY | CHAT | MAP
    type: INVENTORY
    code-length: 5
    blocked-commands: true
```

`code-length` se usa en los tipos `CHAT` y `MAP`. Con `blocked-commands: true` no se puede
usar ningún comando hasta resolver el captcha; `/login` y `/register` quedan bloqueados
igual.

## La comprobación de "ya está online"

```yaml title="config.yml"
security:
  bypass-online-check-with-same-address: true
```

Normalmente, si alguien se conecta con un nick que ya está online, lo rechaza. Con esto
activado no lo rechaza cuando la conexión nueva viene de la misma IP con la que está
registrada la cuenta, que es lo que pasa cuando a un jugador se le cae la conexión y vuelve a
entrar antes de que el servidor se dé cuenta.
