---
title: Sesiones de login
description: Deja que el jugador que vuelve enseguida se saltee la contraseña.
---

Si un jugador se reconecta al poco tiempo de salir, se saltea la contraseña. La sesión se
abre cuando se desconecta, queda atada a la IP que tenía, y se gasta la primera vez que se
usa: cada desconexión te da una sola reconexión.

```yaml title="config.yml"
Security:
  session:
    enable: true
    # Minutos que la sesión sigue abierta. 0 desactiva las sesiones, igual que enable: false.
    timeout: 5
```

## Qué cierra una sesión

Las sesiones se tiran abajo cuando:

- se cambia la contraseña
- se activa o se desactiva el 2FA
- se borra la cuenta
- alguien ejecuta `/pklogin reload`
- se reinicia el servidor: viven solo en memoria

## Qué prueba en realidad la comprobación de IP

<Callout type="warn" title="Minutos, no horas">
  Una IP no es una persona: la comparten todos los que están detrás del mismo router, de una
  red pública o de una compañía de datos móviles. Mientras la sesión está abierta, cualquiera
  con esa IP que escriba el nick del jugador entra sin contraseña, y sin el código 2FA si la
  cuenta tiene 2FA. Unos minutos es una apuesta razonable para cubrir una caída de conexión;
  unas horas es dejar la puerta abierta.
</Callout>

## Con varios servidores de auth

Las sesiones viven en la memoria del servidor que las abrió. En una red con más de un
servidor de auth, una sesión abierta en uno no la conocen los demás, así que al jugador que
caiga en otro backend le van a pedir la contraseña de nuevo.
