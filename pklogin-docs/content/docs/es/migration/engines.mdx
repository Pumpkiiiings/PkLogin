---
title: Migrar entre motores
description: Copia todas las cuentas a otro motor de base de datos sin empezar de cero.
---

`/pklogin migrate <motor>` copia todas las cuentas del motor que estás usando a otro, así que
cambiar no significa empezar de cero.

## Pasos

<Steps>

<Step>

### Rellena los datos de conexión del destino

Edita el bloque `Database` con los datos del motor al que te mueves, pero deja `type`
apuntando al motor en el que estás ahora:

```yaml title="config.yml"
Database:
  type: sqlite          # sigue siendo el motor actual

  host: localhost
  port: 5432            # PostgreSQL, no el 3306 por defecto
  database: pklogin
  username: pklogin
  password: "..."
```

</Step>

<Step>

### Ejecuta la migración

```
/pklogin migrate postgresql
```

Destinos válidos: `sqlite`, `h2`, `mysql`, `mariadb`, `postgresql`.

La copia corre de forma asíncrona e informa del progreso cada 100 cuentas.

</Step>

<Step>

### Cambia y reinicia

Cambia `Database.type` al motor nuevo y reinicia el servidor. `/pklogin reload` no reabre la
conexión.

```yaml title="config.yml"
Database:
  type: postgresql
```

</Step>

</Steps>

## Qué no toca el comando

- **No borra nada.** La base de datos original queda exactamente como estaba, y ese es tu
  rollback: vuelve a poner `type` como estaba y reinicia.
- **No modifica `config.yml`.** El cambio lo haces tú, después de comprobar la copia.

## Se puede repetir

Las cuentas ya presentes en el destino se saltan, así que una segunda ejecución solo copia lo
que falta.

<Callout type="warn" title="Comprueba el puerto antes de migrar">
  El `port: 3306` que viene por defecto es correcto para MySQL y MariaDB. PostgreSQL escucha
  en **5432**. Una migración apuntada al puerto equivocado falla al conectar en vez de a
  medio camino, pero sigue siendo un reinicio desperdiciado.
</Callout>
